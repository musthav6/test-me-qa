# Тест-кейси Test-Me

Кожен кейс оформлено за зразком із завдання (TM-CHECKOUT-001): ID, назва, пріоритет, тип, адреса, передумови, тестові дані, кроки з очікуваними результатами, післяумова.

- **Пріоритет:** високий — гроші, основний сценарій покупки, безпека й ізоляція даних; середній — важливі правила ТЗ; низький — допоміжне.
- **Нове середовище:** в UI — кнопка «↻ Почати заново» з підтвердженням; в API — `POST /api/workspaces` і заголовок `X-Workspace-Token`. Автотести створюють середовище через API і передають token магазину до його старту: результат той самий — порожні кошик, обране, замовлення й відгуки.
- **Ціни:** API повертає копійки (`240000`), UI показує гривні («2 400,00 грн»). У кейсах суми в гривнях.
- **Тестові дані:** наведено для поточного каталогу (16 товарів, p01–p16). Автотести не прив'язані до id і цін: товар підбирається за властивістю (наприклад, «у наявності, від 1 500 грн»), очікувані суми рахуються за правилами ТЗ.
- **Кроки «вручну»** перевіряються під час ручного проходу; решта кроків автоматизована.
- **Що зафіксувати під час виконання** (для кожного кейсу): фактичний результат, статус Passed / Failed, а при розбіжності — докази дефекту. В автотестах це робить звіт Allure: порівняння фактичного й очікуваного в повідомленні про помилку, для UI — скріншот і URL сторінки в момент падіння.
- **Контактні дані** вигадані.

## TM-CHECKOUT-001

**ID:** TM-CHECKOUT-001\
**Назва:** Оформлення замовлення із промокодом WELCOME10 та стандартною доставкою.\
**Пріоритет:** високий.\
**Тип:** позитивний, наскрізний UI-сценарій.\
**Адреса:** https://test-me.vzl.one/

**Передумови:** сайт доступний; створено нове середовище кнопкою «Почати заново» з підтвердженням; кошик, обране та список замовлень порожні. У каталозі доступні «Бездротові навушники “Орбіта”» (`p01`) за 2 400 грн.

**Тестові дані:** 1 пара навушників; промокод `WELCOME10`; стандартна доставка; ім'я «Денис Тестовий»; email `test@example.test`; адреса «Венеція, Юності 1»; результат тестової оплати «Успішна оплата». Усі контактні дані вигадані.

| Крок | Дія | Очікуваний результат |
|---|---|---|
| 1 | У каталозі знайти навушники «Орбіта» та натиснути «До кошика». | З'являється повідомлення про додавання; лічильник кошика показує 1. |
| 2 | Відкрити кошик. | Є одна позиція навушників, кількість 1, ціна товару 2 400 грн. |
| 3 | Увести WELCOME10 і натиснути «Застосувати». Залишити стандартну доставку. | Товари — 2 400 грн; знижка — 240 грн; доставка — 0 грн; разом — **2 160 грн**. |
| 4 | Заповнити контактні поля тестовими даними; вибрати «Успішна оплата». | Дані прийнято, кнопка оформлення доступна, помилок валідації немає. |
| 5 | Один раз натиснути «Оформити замовлення». | Відображається повідомлення про успіх; відкривається «Мої замовлення»; створено рівно одне замовлення зі статусом «Підтверджено» та сумою 2 160 грн; лічильник кошика — 0. |
| 6 | Відкрити «Деталі замовлення». | Навушники × 1; товари — 2 400 грн, знижка — 240 грн, доставка — 0 грн. Відображається номер замовлення. |
| 7 | Перезавантажити сторінку «Мої замовлення» та повторно відкрити кошик. | Те саме замовлення зберегло номер, статус і суму; дубліката немає; кошик порожній. |

**Післяумова:** у власному середовищі залишилось одне тестове замовлення. Не змінюйте чужі дані; для наступного незалежного сценарію створіть нове середовище.

**Автотест:** UI-тест проходить кроки 1–7 і додатково через API перевіряє, що на сервері рівно одне замовлення з тим самим номером. API-тести перевіряють те саме правило без браузера: `approved` → 201, статус `confirmed`, суми за ТЗ; `GET /api/orders/{id}` повертає ті самі товари й суми. **Дефект:** —
